- **Restore `statement_timeout=60000` on `alphard-web::execute_query` via `SET LOCAL`** (Closes #428). The earlier auth-path fix for #421 dropped the 60 s server-side statement timeout because libpq discarded the DSN password when the timeout was passed via psycopg's `connect(..., options="-c statement_timeout=60000")` kwarg under the alphard-web `network_mode: host` + scram-sha-256 setup (the `fe_sendauth: no password supplied` regression). TDD-verified: the test fails on the pre-fix branch tip and passes on this PR's tip. The H-NETWORK-DETECT (#232) contract is preserved for `alphard-web` without the libpq footgun.

- **Strip leaf server certs from `scripts/fetch_tinkoff_gost_ca.py` + regenerate committed bundle** (Closes #482, Closes #488). The committed `docker/certs/tinkoff-gost-ca-bundle.txt` at HEAD `fce907b` carried 2 leaf server certs (`CN=*.tinkoff.ru`, `CN=iss.moex.com`) alongside the 5 CA certs — `ssl.SSLContext.load_verify_locations` silently swallowed them as non-CA X.509 entries but `openssl x509 -in <cert> -noout -dates` against the file showed two `CA:FALSE` entries with 4-11 week expiry (the `*.tinkoff.ru` leaf expires `Sep 30 14:21:05 2026 GMT`, the `iss.moex.com` leaf `Nov 17 23:59:59 2026 GMT`). Root cause: `fetch_chain` returned the raw `[leaf, intermediate, root]` chain that `openssl s_client -showcerts` produces, and `write_bundle` wrote whatever it was given with no CA-vs-leaf filter — the `# Russian Trusted Root CA + Sub CA chain` header described the intent, not the content. Fix: new `_drop_leaf(certs)` helper walks the front of the chain and strips ALL leading leaf certs (`basicConstraints CA:TRUE` is the discriminator, parsed via `cryptography.x509` stdlib so the openssl-less alphard-bot alpine contract is preserved), not just index 0; verified against `iss.moex.com` which duplicates its leaf at index 0 AND index 1 (a TLS-extension quirk where the server includes the leaf twice in its handshake message); wired into both `fetch_chain` (openssl path) and `_fetch_chain_python` (Python 3.13+ stdlib fallback). The committed bundle regenerates to 5 certs, all CAs — `Russian Trusted Sub CA`, `Russian Trusted Root CA`, `ZeroSSL RSA DV SSL CA 2`, `Sectigo Public Server Authentication Root R46`, `USERTrust RSA Certification Authority`. `_is_ca_cert(der)` parses `basicConstraints` via `cryptography.x509` (a project dep used by `_fetch_chain_python` for the bytes-shaped-chain fix in #464), so the leaf-strip path works on the openssl-less alpine host too — without this refactor `_drop_leaf` would raise `RuntimeError("chain has N cert(s) and none is a CA...")` on the alphard-bot alpine image, breaking the contract that #454/#464 were careful to preserve. New regression tests pin the openssl-less contract: `test_is_ca_cert_uses_stdlib_not_openssl_cli` (asserts `subprocess.run` is never called from `_is_ca_cert` and that a real CA cert returns `True` while a real leaf cert returns `False`) and `test_fetch_chain_python_does_not_require_openssl_for_leaf_filter` (asserts the full chain flows through `_drop_leaf` on a host where `openssl` CLI is missing, by making `subprocess.run` raise `FileNotFoundError`). `tests/test_454_gost_ca_fetcher.py` is widened to assert `_drop_leaf` strips all leading leaves (5-block chain → 3 CAs returned, 2 leaves at front), refuses to ship a leaf-only chain (raises `RuntimeError` if every cert is a leaf), and the existing tests are patched to mock `_is_ca_cert` so they don't need a real DER-encoded CA fixture. New regression test `tests/test_455_gost_wiring.py::test_gost_bundle_every_entry_is_a_ca_cert` widens the at-least-one-CA assertion: parse every PEM block in the committed bundle, invoke `openssl x509 -noout -ext basicConstraints` per block, and fail if any cert lacks `CA:TRUE` — a regression that re-adds a leaf (e.g. via reverting `_drop_leaf`) fails this test on branch tip before merging. `tests/test_454_gost_ca_fetcher.py::test_script_does_not_use_tempfile_in_fetch_chain` pins the dead-tempfile-in-`fetch_chain` defect #454 reported — `_is_ca_cert` no longer uses `tempfile.NamedTemporaryFile` for its openssl subprocess call (it parses via stdlib `cryptography.x509` instead), but the dead-tempfile-in-`fetch_chain` defect #454 reported stays pinned. `cryptography` is added to both `requirements.txt` and `requirements-ci.txt` (was previously transitive via `t-tech-investments`) so a future Tinkoff-SDK dep-cleanup cannot silently remove the only stdlib-based CA-detection path. 1786/1786 tests pass (40 in `test_454` + `test_455` GOST suite).

Smoke gate: 1800/1800 pass. The bind-mount chicken-and-egg from issue #441 is now closed: both `quickstart.sh` AND `pre_pr_smoke.sh` generate the file before compose reads it.

- **Fix GOST CA fetcher pure-Python fallback crash on Python 3.13/3.14** (Closes #464, Related to #461). `_fetch_chain_python` called `c.public_bytes(serialization.Encoding.DER)` on each member of `ssock.get_verified_chain()`. On CPython 3.13+ that method already returns `bytes` objects (raw DER) per [CPython #118658](https://github.com/python/cpython/issues/118658), so `c.public_bytes(...)` raised an uncaught `AttributeError` that propagated out of `main()` instead of being caught by the `except ImportError:` branch — breaking the openssl-less deployment contract on the very Python version it was designed for. Production impact: any alphard-bot container built without openssl CLI (alpine, slim, distroless) running Python 3.13+ would fail to generate the GOST CA bundle and exit with a traceback. The fallback now branches on `isinstance(c, (bytes, bytearray, memoryview))` to handle the 3.13+ default, and keeps the cryptography-based `public_bytes(Encoding.DER)` path as a secondary for older builds that still return `cryptography.x509.Certificate` objects. New regression tests `test_fetch_chain_python_handles_bytes_chain` and `test_fetch_chain_python_attributeerror_no_longer_uncaught` pin both contracts; `test_main_returns_one_when_no_certs_extracted` is widened to stub the fallback now that it is reachable from `main()`'s outer `RuntimeError` handler.

- **Fix three logic defects in `scripts/fetch_tinkoff_gost_ca.py`** (Closes #454). Defect 2: `_parse_pem_blocks` raised `binascii.Error` on empty PEM bodies and the except-clause did not catch it, so a half-rendered handshake produced a hard exception. When MOEX returns rows with `volume=0 / VOLUME=0` (illiquid sessions, last-trade-day entries, delisted-ticker trailing bars), the old chain silently substituted NUMTRADES (typically 1..150) and persisted it as if it were shares/papers — then `_log_returns` / `cross_source` / `_zscore_threshold_filter` accepted the fabricated bars as legitimate. After the fix, `volume == 0` is the truthful signal (accurate silence beats wrong data). 3 new regression tests in `tests/test_moex_bonds.py` pin: bonds `VOLUME=0 → volume=0`, bonds `VOLUME=None → volume=0`, and shares `volume=0 + NUMTRADES=N → volume=0`. (Closes #364, PR #368.)
- **`scripts/pre_pr_smoke.sh` — refuse to run against a non-local Docker daemon**. Pre-fix, the script unconditionally ran `docker compose up` whenever invoked; if an operator's shell exported `DOCKER_HOST=tcp://...` (ssh/tcp context), the smoke gate would happily exercise the wrong stack — a Category 1 risk on shared LXC hosts where "local" and "remote" daemons share credentials. New guard runs *before* the cleanup trap is registered: if `[[ "${DOCKER_HOST:-}" =~ ^tcp:// ]]` and `ALLOW_NONLOCAL_SMOKE != 1`, exit 9 with a clear message. Opt-in escape hatch `ALLOW_NONLOCAL_SMOKE=1` prints a WARNING and proceeds. Defense-in-depth: 6-test regression guard in `tests/test_smoke_refuses_remote_docker_host.py` pins guard-before-trap ordering, ALLOW_NONLOCAL_SMOKE escape, exit-code-9 distinctness, and that the local-docker happy path is unaffected. (Closes #363 follow-up + #370, PR #369.)

## How to add a new entry

1. Open the PR for your fix/feat.
2. After merge, add an entry to the `[Unreleased]` section above, grouped
   under `Added` / `Fixed` / `Changed` / `Tests` / `Maintenance` / `Documentation`.
3. Reference the PR number and (if applicable) the closing issue.
4. **Only list PRs that have actually merged.** Open PRs go in the Kanban
   board, not here, until they land.
5. On release: cut a new `## [X.Y.Z] - YYYY-MM-DD` section, move the
   `[Unreleased]` items under it, bump `pyproject.toml` `version`, tag the
   commit (`git tag -s vX.Y.Z -m 'release X.Y.Z'`).

A future release-notes extraction tool (per issue #289 acceptance criteria)
will auto-extract entries from `git log --grep '^fix\|^feat' vX.Y.Z..HEAD`
so this hand-curation step is the single source of truth only until then.
The script does not yet exist — it is the planned future automation.

## Path-existence guard (CI)

To prevent the regression filed in [Issue #310](https://github.com/m0rtal/alphard/issues/310)
(`CHANGELOG.md` claiming source paths that do not exist), the CI pipeline
runs the following check against every change to this file:

```bash
grep -oE '`(src|scripts|docs|tools)/[A-Za-z0-9_./-]+`' CHANGELOG.md \
  | tr -d '`' | sort -u | while read -r p; do
      [ -e "$p" ] || { echo "CHANGELOG references missing path: $p"; exit 1; }
  done
```

(The exact tool path is intentionally left un-quoted in this guard
description — see the actual shell command above.)

A future improvement (tracked under issue #289 acceptance criteria) is to
move this guard into the planned release-notes tool and run it on every
release.
