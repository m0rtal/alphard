All notable changes to **Alphard** are documented in this file. The format
follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the
project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html)
(`pyproject.toml` `version` is the source of truth for the current release).

> **Source of truth.** This file is curated by hand from `git log` (which is
> the authoritative source for SHAs) and cross-referenced with
> [`docs/PHASE2-ROADMAP.md`](docs/PHASE2-ROADMAP.md),
> [`docs/decisions/`](docs/decisions/) (ADRs), and the per-PR descriptions.
> Auto-extraction is left to a future release-notes tool (see
> [Issue #289](https://github.com/m0rtal/alphard/issues/289)).

### Removed
- **Grafana and Prometheus removed from the compose stack** (Closes #395, PR #399). The `docker/grafana/` and `docker/prometheus/` directories are deleted; the `alphard-grafana`, `alphard-prometheus`, and `alphard-chownfix` services are dropped from `docker-compose.yaml`; the obsolete top-level `version: "3.9"` key is removed. With `alphard-web` (PR #394) replacing the Grafana phase28 dashboard as the operator UI, the observability surfaces no longer need a separate Grafana stack — direct SQL to `alphard-postgres` serves every metric the four-panel dashboard showed. The `alphard-chownfix` sidecar is gone because its sole purpose was to set ownership on Grafana/Prometheus leaf directories; with both gone, there is no work left for it. `tests/test_compose_structure.py` is rewritten with **negative assertions** that the three removed services stay removed — so any future PR that re-adds Grafana or Prometheus by accident is caught immediately. `alphard-prometheus-data` named volume is also dropped. The bot, postgres, and redis services are unchanged. Operators should pull `alphard-web` separately (PR #394) before merging #399 so the dashboard is live before the Grafana URL 502s. (PR #399, Closes #395.)

### Added
- **`scripts/daily_incremental.py`** — daily closed-bar refresh orchestrator. For each `backfill_complete=TRUE` ticker: `start = latest_db_ts + 1`, `end = today - 1`, source = `tinkoff_grpc` (fallback `moex_iss`). Never inserts today's bar (still forming); never re-fetches history already in DB. Defensive `b.ts <= end` filter guards against Tinkoff occasionally returning today's incomplete bar. Driven by cron once per day post-market-close. (PR #332.)
- **`ohlcv_daily` row accumulation gauge** + Grafana panel — surfaces backfill drift between Tinkoff MD archive and broker gRPC. (PR #294, #290)
- **Universe coverage gauges** (`alphard_tickers_in_universe_total`, `alphard_tickers_with_full_history_total`, Phase 2.8 step 2). (PR #243)

New `tests/test_413_el_helper_on_handler_sink.py` (177 LOC, 4 tests) pins the contract: `el()` no longer accepts `on*` keys; surviving branches (className, dataset, attributes) stay regression-clean. - **`scripts/quickstart.sh` — dead `--profile` scaffolding and a 404 next-steps URL removed** (Closes #402, Closes #403). PR #399 deleted the only three services that declared `profiles: ["observability"]`, which left `ALPHARD_PROFILE` threading through 9 code sites where every value selected the identical three-service set, and an `if [[ "$PROFILE" == "observability" ]]` branch whose two arms had converged. The success path also advertised `alphard-web` at `http://localhost:8080/`, a connection-refused for any operator who followed it, since that service ships in the still-open PR #394. - **`FallbackDataLoader` — per-ticker/per-source `_skip` memoisation short-circuits known-empty sources** (PR #373). The fallback chain iterated every source for every ticker with no memoisation of the "this source has nothing on this ticker" decision, so the supervisor was observed (2026-09-01) spending ~5 s per foreign SPBXM ticker even when both broker gRPC and MOEX ISS return `LoaderNotFoundError` / zero rows. `FallbackDataLoader` now holds `self._skip: dict[ticker, set[source_name]]`; when a source raises `LoaderNotFoundError` or returns zero rows for a ticker, that source is marked known-empty and subsequent `iter_ohlcv` calls skip past it **before** any HTTP / gRPC I/O is attempted. Cache lifetime matches the supervisor subprocess, so it resets naturally on subprocess restart between backfill runs — there is no explicit invalidation and no eviction, because the bound is `tickers × sources` (~3300 × 2 ≈ 6600 entries max). Complements the #377 ISIN-prefix universe filter: #377 stops the zero-yield tickers entering the universe, #373 makes the residual per-source misses cheap. 4 regression tests in `tests/test_fallback_loader_skip_cache.py` cover successful-fetch caching, `LoaderNotFoundError` caching, zero-bars caching, and per-ticker isolation. (PR #373.)
- **`scripts/pre_pr_smoke.sh` — smoke override file redefines every hardcoded `container_name:` to a per-PID-scoped equivalent, and re-adds `alphard-postgres` as a network alias** (Closes #379). PR #376's `COMPOSE_PROJECT_NAME=alphard-smoke-$$` scoping is not enough — `docker-compose.yaml` hardcodes `container_name: alphard-bot / alphard-postgres / alphard-redis / alphard-prometheus / alphard-chownfix / alphard-grafana`, and Docker Compose honours those literal names without prefixing them with the project name. On a host where the operator's stack is already running, smoke gate step [1/4] fails with `Conflict. The container name "/alphard-bot" is already in use` even with `COMPOSE_PROJECT_NAME=alphard-smoke-<PID>`. PR #378's `docker rm alphard-chownfix` cleanup does not address the root cause and rests on a factually incorrect premise about `-p` flag behaviour (`docker compose config` on this host confirms Compose 2.40 ignores `!reset null`). Override file now redefines every hardcoded `container_name` with `${COMPOSE_PROJECT_NAME}-<service>-1` (matching Compose's project-scoped default), and re-adds `alphard-postgres` as a network alias so the bot entrypoint (which hardcodes hostname `alphard-postgres`) resolves postgres inside the smoke's `alphard-net`. Belt-and-suspenders: chownfix-orphan cleanup from PR #378 is retained for #379 AC #3. 5 new tests in `TestSmokeContainerNameOverride` pin override-file content, alias matching, unquoted heredoc variable expansion, chownfix cleanup preservation, and the `alphard-postgres` alias requirement. - **`TinkoffInvestMDDataLoader.list_shares_all` — drop tickers with `ISIN` prefix `US` at universe-construction time** (Refs #375). SPBXM-foreign tickers (e.g. `AAPL=US0378331005`) have ISINs starting with `US`; account `m0rtal` returns `LoaderNotFoundError` for these FIGIs (no broker-side grant) and MOEX ISS returns 0 rows (these tickers trade on SPB Exchange, not MOEX). - **`scripts/pre_pr_smoke.sh` — scope every compose invocation to a per-PID project name** (`COMPOSE_PROJECT_NAME=alphard-smoke-$$`, Closes #374). Pre-fix, the script's cleanup trap ran `docker compose down -v` and silently reused the operator's existing `alphard-postgres` / `alphard-bot` containers (`docker-compose.yaml` hardcodes `container_name:`), wiping their volumes. Compounding failure: the pytest helper used `subprocess.run(timeout=...)` and dropped the child on `TimeoutExpired` without killing it, so the orphaned subprocess's EXIT trap fired ~90 s later and tore down the operator's stack while the test had already returned green. Two minimal fixes: derive `COMPOSE_PROJECT_NAME` from `$$` and pass `-p "$COMPOSE_PROJECT_NAME"` on every compose invocation (container names become `alphard-smoke-<PID>-postgres-1` / `alphard-smoke-<PID>-alphard-bot-1`, fully isolated from the operator's stack); and switch the test helper to `subprocess.Popen` + `proc.kill()` in the `TimeoutExpired` branch so the smoke's cleanup trap cannot fire after the test returns. `docker exec` / `docker inspect` calls route through `$SMOKE_BOT` / `$SMOKE_PG` aliases instead of hardcoded names. New `TestSmokeProjectIsolation` (4 pinning tests) covers the project-name derivation, the `-p` flag propagation, the `TimeoutExpired` kill branch, and that operator-stack names remain untouched. Out of scope: removing `container_name:` from `docker-compose.yaml` (multiple external scripts hardcode `alphard-postgres`/`alphard-bot` — `backup_database.py`, `init_postgres.sh`, `backfill_spbxm_universe.py`, `quickstart.sh`, Portainer API consumers; project-name isolation is the least-invasive defence). (PR #376.)
- **`scripts/pre_pr_smoke.sh` — broaden DOCKER_HOST guard from `tcp://` only to deny-by-default on any non-`unix://` scheme** (Closes #371). The cycle145 guard (PR #369) matched only `DOCKER_HOST=tcp://...`, so an SSH Docker context (`DOCKER_HOST=ssh://user@host`) bypassed the guard and would still trigger `docker compose down -v` against a remote stack on EXIT-trap. Invert the predicate: only `DOCKER_HOST=unix://...` is local; every other scheme (`tcp`, `ssh`, `fd`, `npipe`, future) requires explicit `ALLOW_NONLOCAL_SMOKE=1`. User-facing messages updated to drop the "production" wording that no longer fits every remote scheme; comment block retargeted from #363 follow-up to #371. New `test_guard_does_not_whitelist_tcp_only` (structural) fails if a future refactor re-introduces a bare `^tcp://` predicate. (PR #372.)
- **`pg-init` service dropped from `docker-compose.yaml`; schema application moved into `docker/entrypoint.sh` before the fail-closed auth probe.** Pre-#347, pg-init bind-mounted single-file SQL paths (`./docker/postgres/init.sql:/sql/docker_postgres_init.sql:ro` and `./src/data/schema.sql:/sql/src_data_schema.sql:ro`) that render as **directories** on PVE LXC hosts — the schema was never applied and `_auth_probe` was missing, so the bot's fail-closed auth probe aborted every container start and the pre-PR smoke gate could not bring up `alphard-bot`. With pg-init removed, the bot's own `init_schema()` (already idempotent — `CREATE TABLE IF NOT EXISTS` / `ADD COLUMN IF NOT EXISTS` throughout `src/data/schema.sql`) is the only schema source, and the entrypoint now runs it before `auth_probe()` so the probe table exists on every boot, fresh volume or preserved volume alike. `tests/test_347_pg_init_removal.py` (5 pure-fs tests) pins the post-fix contract: no `pg-init` service, no `pg-init` in `alphard-bot.depends_on`, `init_schema()` precedes `auth_probe()`, smoke gate does not bring up `pg-init`, and `_auth_probe` is still created by `src/data/schema.sql`. 1548 tests pass / 37 skip (delta −2 from removed pg-init tests; net +5 new tests). (Closes #347, PR #349.)

- **`FallbackDataLoader.iter_corporate_actions` now chunks windows exceeding a source's `MAX_LOOKBACK`** — same defect class as #346 (closed by PR #348 for OHLCV) but on the corporate-actions path. Pre-fix, the outer window was passed straight to every source in the chain; `MOEXDataLoader` enforces a 1825-day cap on `iter_corporate_actions` (line 202) and any supervisor call whose broker gRPC fetch returned 0 actions fell through to `moex_iss` and aborted with `LoaderError: range ... exceeds upstream max lookback 1825d`, silently losing the synthetic delisted-event signal the backtester needs to flag a ticker as no longer tradeable. Fix mirrors PR #348's OHLCV fix: a new `_iter_source_corp_actions` helper, wired through `_source_max_lookback`, splits the request into `<= cap` sub-ranges and concatenates them; sources without a declared cap receive the full window. Partial-chunk success followed by a later-chunk raise marks the source failed (no rows yielded). Three regression tests in `tests/test_fallback_loader.py` cover: 9-year-window chunking into two sub-ranges, no-chunking-when-window-fits-cap, and partial-failure-marks-source-failed. 1544 tests pass / 37 skip (delta −1 vs cycle133: net +3 new tests). (Closes #349.)
- **`scripts/daily_incremental.py` — `_fetch_with_fallback` now routes through `FallbackDataLoader`** instead of inlining its own broker-first → MOEX chain. Pre-fix, the inline chain on line 89 called `MOEXDataLoader().iter_ohlcv(ticker, start, end)` directly with the full outer window; MOEX enforces a 1825-day cap and any longer window raised `LoaderError: range ... exceeds upstream max lookback 1825d`. For delisted tickers with stale `latest_db_ts` the window is often years long, so each daily-incremental run silently lost every such ticker's incremental update on the days broker gRPC happened to fail. The chain uses `FallbackDataLoader.iter_ohlcv` so per-source lookback-aware chunking (PR #348) applies automatically, and broker construction is wrapped in `try/except` so the documented `ALLOW_NO_BROKER=true` Phase 0 stub mode / no-token dev runs silently degrade to MOEX (`FallbackDataLoader._resolve` skips `None` sources). Four regression tests in `tests/test_daily_incremental.py` cover: 9-year-window chunking into multiple sub-ranges, chain-routing (broker `fetch_ohlcv` is not called directly), no-token broker constructor failure skips to MOEX, and MOEX not invoked on the happy path. (Closes #350, #354.)
- **`_is_complete()` rebases floor on earliest DB bar**, not on the optimistic `listed_at`. The previous floor-source was `ticker_universe.listed_at`, populated by `Instrument.list_*` falling back to `first_1min_candle_date` / `ipo_date` — those fields predate real OHLCV availability by years for SPBXM ETFs and many similar instruments, so `expected_bars` ballooned to ~5000 when only ~570 are fetchable, leaving 27/3265 (0.8%) tickers stuck in perpetually-incomplete state with 58k bars written. After-load rebase asks the right question: "have we pulled all the data the API will actually give us?" instead of "have we pulled data that doesn't exist?". (Closes #319, #332.)

The pre-fix operator dashboard interpolated server-controlled JSON fields (`figi`, `listed_at`, `delisted_at`, `kind`, `msg`, bar OHLCV values, `cbr_key_rate`) directly into `innerHTML` via template literals at 8 sites: `renderDash` (r-backfill, r-daily, r-drawdown, r-backup-files, the events table), `renderUniverse` (each row's ticker/figi/status/badge/last_bar_at), `renderBackfill` (r-bf-pct), `renderMacro` (r-macro-cbr), `renderBackups` (each row), and `openDrawer` (the drawer body — the highest-impact sink since `figi` is user-editable broker metadata). A malicious ticker with `figi=`<img src=x onerror=alert(document.cookie)>` would execute arbitrary JS in the operator's browser on any page that opens the drawer. Fix uses the existing `el()` helper (now hardened — the `html` props DSL branch is removed so no caller can pass raw HTML) to build DOM nodes; text values are inserted via `createTextNode` so the browser never parses them as HTML. Static regression guard `tests/test_web_xss_static.py` (6 tests) blocks any future PR that reintroduces a template-literal `innerHTML` assignment: scans `index.html` for the pattern, asserts the `el()` helper has no `innerHTML` reference, and pins that `textContent` / `createElement` are still in use. End-to-end verified on this dev host: 6/6 XSS static tests pass; 13/13 auth tests pass; 1691 total tests pass / 34 skip / 0 fail; flake8/black/mypy clean. (PR #394 followup.)
- **`src/web/server.py` — bearer-token auth gate on every `/api/*` endpoint except `/api/health`, plus loopback-only default bind** (Closes #406). The pre-fix dashboard had zero authentication: `/api/settings` returned DSN-derived values and token-set flags, `/api/backups` listed files under `ALPHARD_BACKUP_DIR`, `/api/tickers` and `/api/ticker/<sym>` returned the full universe with broker metadata, all reachable on `0.0.0.0:8080` from any LAN peer. Fix layers two defences. (1) `check_auth(path, authorization_header)` in `src/web/server.py` is a pure function that reads `ALPHARD_WEB_TOKEN` from the env; if unset/empty the gate fails open (dev mode), otherwise every protected path requires `Authorization: Bearer <token>` with `hmac.compare_digest` constant-time comparison. `/api/health` is exempt so the container healthcheck keeps working. Failed auth returns 401 with `WWW-Authenticate: Bearer realm="alphard-web"`. (2) `make_server()` default bind flips from `0.0.0.0` to `127.0.0.1`; operators who really need LAN access set `ALPHARD_WEB_HOST=0.0.0.0` and combine it with the bearer gate. `docker-compose.yaml` pins both contracts: `ports: 127.0.0.1:8081:8080` and `ALPHARD_WEB_TOKEN: ${ALPHARD_WEB_TOKEN:-}` in the alphard-web service. `tests/test_compose_structure.py::TestAlphardWebSecurity` (2 structural tests) refuses any future compose refactor that drops either invariant. 13 new tests in `tests/test_web_server.py` cover `check_auth` pure-function paths (unset, empty, wrong scheme, open path, HTML root, matching bearer) and the HTTP integration paths (401 with header, 401 with wrong bearer, 200 with right bearer, 200 with no token env, /api/health exemption, unknown-path gate, WWW-Authenticate challenge). `.env.example` documents `ALPHARD_WEB_TOKEN` and the `head -c 32 /dev/urandom | base64` generation recipe. End-to-end smoke on this dev host: live HTTP server with `ALPHARD_WEB_TOKEN=test-token-12345` returns 401+WWW-Authenticate for no-auth / wrong-bearer, 500 for correct-bearer (DB unreachable as expected, auth gate passed), 503 for /api/health (DB unreachable, gate open as expected). 1691 total tests pass / 34 skip / 0 fail; flake8/black/mypy clean. ## How to add a new entry

1. Open the PR for your fix/feat.
2. After merge, add an entry to the `[Unreleased]` section above, grouped
   under `Added` / `Fixed` / `Changed` / `Tests` / `Maintenance` / `Documentation`.
3. Reference the PR number and (if applicable) the closing issue.
4. **Only list PRs that have actually merged.** Open PRs go in the Kanban
   board, not here, until they land.
5. On release: cut a new `## [X.Y.Z] - YYYY-MM-DD` section, move the
   `[Unreleased]` items under it, bump `pyproject.toml` `version`, tag the
   commit (`git tag -s vX.Y.Z -m 'release X.Y.Z'`).

A future release-notes extraction tool (per issue #289 acceptance criteria)
will auto-extract entries from `git log --grep '^fix\|^feat' vX.Y.Z..HEAD`
so this hand-curation step is the single source of truth only until then.
The script does not yet exist — it is the planned future automation.

## Path-existence guard (CI)

To prevent the regression filed in [Issue #310](https://github.com/m0rtal/alphard/issues/310)
(`CHANGELOG.md` claiming source paths that do not exist), the CI pipeline
runs the following check against every change to this file:

```bash
grep -oE '`(src|scripts|docs|tools)/[A-Za-z0-9_./-]+`' CHANGELOG.md \
  | tr -d '`' | sort -u | while read -r p; do
      [ -e "$p" ] || { echo "CHANGELOG references missing path: $p"; exit 1; }
  done
```

(The exact tool path is intentionally left un-quoted in this guard
description — see the actual shell command above.)

A future improvement (tracked under issue #289 acceptance criteria) is to
move this guard into the planned release-notes tool and run it on every
release.
